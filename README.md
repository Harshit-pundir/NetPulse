# 📖 Overview

**NetPulse --- Network Monitoring & Health Dashboard** is a web-based
application designed to provide a centralized view of registered network
devices and their monitoring status.

The application allows users to manage devices, view monitoring results,
track alerts, and review recent activity. A background monitoring worker
periodically checks registered devices and stores monitoring information
in the database.

The backend is built with **FastAPI**, while the application uses the
**Supabase Python Client** to communicate with an existing **Supabase
PostgreSQL** database.

# 🧠 How It Works

``` text
                 User / Browser
                       |
                       v
             HTML, CSS & JavaScript
                       |
                       v
                  FastAPI
                       |
             API Routes / Services
                       |
                       v
          Centralized Supabase Client
               (app/database.py)
                       |
                       v
             Supabase PostgreSQL
                       ^
                       |
              Monitoring Worker
                       |
              Periodic Device Checks
                       |
             Save Results & Alerts
```

1.  A user interacts with the web interface.
2.  The frontend sends requests to FastAPI endpoints.
3.  FastAPI routes validate and process requests.
4.  Backend services use the shared Supabase client.
5.  The Supabase Python Client reads and writes data in Supabase
    PostgreSQL.
6.  The monitoring worker periodically checks registered devices and
    stores monitoring results and relevant alerts.
7.  The frontend displays the returned information.

# 🗄️ Database

NetPulse uses an existing **Supabase PostgreSQL** database.

A single Supabase client is created in `app/database.py` and imported
wherever database access is required.

Example:

``` python
from app.database import supabase

response = supabase.table("devices").select("*").execute()
devices = response.data
```

The application uses the following existing tables:

  Table                  Purpose
  ---------------------- --------------------------------------
  `users`                Stores application user records
  `devices`              Stores registered device information
  `monitoring_results`   Stores device monitoring results
  `alerts`               Stores monitoring alerts
  `activity_logs`        Stores application activity records

> **Database safety:** Configure the existing Supabase project
> credentials in `.env`. Do not reset or recreate existing tables when
> setting up the application.

# ⚙️ Installation

## 1️⃣ Clone the Repository

``` bash
git clone https://github.com/Harshit-pundir/NetPulse.git
cd NetPulse
```

## 2️⃣ Create a Virtual Environment

### Windows

``` bash
python -m venv venv
venv\Scripts\activate
```

### Linux / macOS

``` bash
python3 -m venv venv
source venv/bin/activate
```

## 3️⃣ Install Dependencies

``` bash
pip install -r requirements.txt
```

## 4️⃣ Configure Environment Variables

Create a `.env` file in the project root:

``` env
SECRET_KEY=your_secret_key
SUPABASE_URL=your_supabase_project_url
SUPABASE_KEY=your_supabase_key
```

Use the appropriate Supabase key for your backend configuration. Never
expose a Supabase secret/service-role key in frontend code or commit
credentials to GitHub.

Make sure `.env` is included in `.gitignore`.

## 5️⃣ Run the Application

If the FastAPI application instance is defined as `app` in
`app/main.py`, run:

``` bash
uvicorn app.main:app --reload
```

Open the application:

``` text
http://127.0.0.1:8000
```

> If your FastAPI entry point or module path is different, use the
> Uvicorn command that matches your actual project structure.
